# Аналитика Глобуса читателей (черновик)
 
Событие `readers_globe_open` отправляется один раз при успешном открытии общего глобуса, не при перемещении карты, обновлении данных или открытии карты библиотеки. Никаких ID аккаунта, имён, друзей, отрывков и результатов чтения в параметры события не добавляем. Analytics сам использует технический идентификатор браузера: число пользователей не равно числу зарегистрированных людей.

## Перед выпуском
1. В Firebase Project settings → Integrations включить Google Analytics (или проверить уже существующую связь).
2. В Project settings → General → Your apps скопировать measurementId нужного web app в firebase-config.js. Без него аналитика не включается.
3. В Google Analytics отключить Google Signals, персонализацию рекламы, расширенное измерение (Enhanced measurement), рекламные интеграции; проверить отсутствие персональных данных в автоматических событиях, URL и настройках. Обновить политику конфиденциальности и убедиться в допустимости обработки данных с учётом тематики приложения. До проверки не включать в production.
4. Проверить добровольное согласие в меню пользователя, включая отказ, отзыв, перезагрузку и несколько вкладок. Аналитика не должна мешать работе приложения при блокировщиках или офлайн. Отдельно проверить открытие общего глобуса, переключение фильтров, обновление друзей и личную карту. В DebugView проверить фактически отправляемые параметры и автоматические события.
5. После тестов выпустить изменения и обновить версию приложения стандартным способом проекта.
6. В Analytics → Reports → Engagement → Events выбрать readers_globe_open: Event count — число открытий, Total users — оценка уникальных браузерных пользователей за период. Отчёт только по согласившимся пользователям. Исторические открытия не восстановить.

Черновик считает открытия; точное время в разделе, посещения других разделов и долю от всех аккаунтов пока не реализует. Для доли нужно отдельно определить знаменатель и согласовать способ измерения.
